# kami-drills v1.1: the 47 v1 drills as v2 specs, with the B-audit fixes

**Status: draft, experimental.** v1.1 is `specs/v1.1/<id>.json` (one spec per v1 drill), `specs/v1.1/MANIFEST.json`
(role, status, fix, reason, content hash per drill), the generator `scripts/v11/` and `tests/test_v11_specs.py`. Nothing
touches `drills/`, the v1 loader, `task.py` or `kami-drills run`. v1.0.0 stays frozen for the live Season 1 forecast. Spec
format, intents and adapter: [v2-spec.md](v2-spec.md).

**Integrated** into `v2/drills` (integration step 2): the specs are regenerated with the one scorer, and the spec package
now has what section 6 asked for (role, manifest-aware `load`, buy intents with the kami index, move vs travel, the full
battery with the timing exemption, `any_of` components, the `*` native key). Section 7 lists what that changed.

```bash
uv run kami-drills spec check specs/v1.1 bank/v2.0-rc8   # bank root via its manifest; exits 0 (smoke/retired passes are "expected")
uv run pytest tests/test_v11_specs.py                           # validates every spec; ranking specs must pass the battery gate
KAMIARENA_DATA=<recorded v1 runs> uv run python scripts/v11/run.py   # rebuild specs/v1.1 + MANIFEST.json (calls `spec from-v1`)
KAMI_DRILLS_PLAYS=<rc2 tries, plays.json> uv run python scripts/v11/eq.py        # mechanical conversion vs v1 on the rc2 tries
KAMI_DRILLS_PLAYS=<rc2 tries, plays.json> uv run python scripts/v11/rescore.py out.json   # v1.1 rescoring, point-biserial
uv run inspect eval kami_drills/adapters/harness_4_7.py -T paths=specs/v1.1 -T policy=oracle --model mockllm/model
```

The 4.7.0 adapter renders 46 of the 47 specs; `repeat-pool-swap-retry` is harness-bound and not rendered. The Inspect oracle
run passes all 46 (`stall-no-kami`'s `buy_kami` oracle now maps to a tool).

## 2. How the specs were made

1. **Game half, mechanically.** A generator (`scripts/v11/conv.py`) turns each v1 drill into an overlay. `fixes.py` applies the fixes, `run.py` builds the suite.
   - Replay rows become intent rows, matched with the same patterns as `h47.to_intents`:
     - `waited_gte` becomes `clock_gte`.
     - The response text is kept as `native` under the key `*` (verbatim on any adapter unless harness-bound).
     - `move_to_room` rows are `travel` with `hop: true` (one adjacent step), `travel_to_room` rows `hop: {not: true}`.
     - Class and reason come from `h47.reason_code`.
     - Default state deltas are added for travel, start, stop, level and revive.
     - Within a verb, specific rows come before catch-alls.
   - The v1 rule maps to intents.
   - Fork state comes from the prefix's last lens reads, plus the acts that followed them.
   - Oracle: `to_intents` of the v1 oracle.
   - Recorded mistake: the source transcript's next calls (in the local recorded v1 runs, `$KAMIARENA_DATA`), hand-picked where the first turn is a read.

   On the 1034 recorded rc2 tries this conversion matches v1 on **1027** (996 before integration: the 31 vendor-drill
   differences came from buy intents that dropped the kami index, now kept). The 7 that differ are cases where v1 was wrong: a dry-run `harvest_start` counted as the harvest (gemini ×2 cooldown-start-wait, opus quest19), a dry-run start was forbidden (grok revive-then-heal, luna unmanaged-lowhp), or `use_item_batch count 3` bypassed the replay's feed gates (sonnet ×2 quest19).
2. **Native half.** `kami-drills spec from-v1` fills the prefix and recorded reads verbatim, pseudonymizes third-party wallets and player records (`spec/pseudonymize.py`, public key `V1_KEY`; owner decision 2026-11-03) and stamps the v1 hash. The test checks it is idempotent. Pseudonymizing kept every `spec check` verdict, the adapter status, the rescore output and the 1027/1034 agreement unchanged.
3. **Fixes.** The audit's fixes, below, were applied as spec edits. `from-v1` was run again on the result.

**Fixes applied to every drill:**

- **Stated objective.** `decision_point.closing` is a user turn at the fork, `Operator goal: …`, mirrored in `objective.drill`. It states the outcome the rule scores, never the move. The audit's inferred-intent drills (travel-not-move, levelup-not-resting, wrong-node-stop) now state their goal.
- **Dry runs.** A dry run is a `quote`, never the act, so a probe is never forbidden and never the answer. The test checks this for every ranking drill: probe the mistake, then play the oracle, and it must still pass.
- **Success forks.** On 13 forks the live agent acted correctly. These get `mistake_class: none` and an `authored-mistake` play (expected 0) instead of a fake recorded one.

## 4. Battery gate (offline, `test_ranking_passes_the_battery_gate`)

Each ranking spec must pass `check.check` with the 4.7.0 adapter, which fails it on any lazy pass of:

- **`check.battery`**: no calls, end_session, wakes of 5/60/1440 min, wait 300 + end, waits ×3, read-then-end,
  dry-run-only, kitchen sink, always-feed, always-revive, always-level, always-stop, always-move, collect-all,
  start-then-level, complete-all-quests, token move, wait-then-mistake, mistake-then-wake and move-to-each-room-then-mistake.
  On success forks the mistake plays use the authored mistake (`is_authored_mistake`).
- **The 4.7.0 native battery**: empty batches, dry-run oracle acts, collect from every kami.

It must also keep the three plays: the oracle passes, the null fails, and the source mistake fails.

**Result: all 27 ranking specs pass**, and `check_bank` over v1.1 plus bank v2.0-rc8 (56 public specs; the 20 private
ones checked locally) reports no failure on any ranking or bank item. One documented exemption covers the 5 pure timing
items (`scoring.timing_item: true`): stale-cooldown-retry-start, repeat-cooldown-start-wait, repeat-stop-cooldown-identical,
repeat-cooldown-feed and memory-sonnet-stamina-unreliable-belief.
- On these, "wait 300, then the recorded act" is the oracle itself. wait_then_mistake passes on four of them, and the
  kitchen sink on stamina.
- `check` allows such a pass only if the play ends in wait 300 + the mistake and fails once that tail is removed. So
  every pass is earned by the wait.

## 5. Re-scoring the recorded v1 tries (sensitivity)

`B-data/plays.json` holds 11 models × 2 tries × 47 drills of tool calls, replayed through the 4.7.0 adapter against each
v1.1 spec. **This is a sensitivity check, not a result.**
- The trajectories were generated under v1: v1 replay answers, v1 early stop (the overpaid stops in first-kami-vendor), no stated objective, and the v1 gap text.
- A model never saw what v1.1 would answer. That is why repeat-cooldown-feed scores 0/22: no v1 try could restart the harvest, because v1 forbade it.

Verdict changes (pass count of 22, v1 → v1.1):

| drill | v1 → v1.1 | why |
|---|---|---|
| repeat-take-trade-underflow | 5 → 9 | 8 small-lot bids now pass; 4 wake/end-only passes now earn 0.5 |
| memory-sonnet-stamina-unreliable-belief | 0 → 9 | behaviour only |
| repeat-stop-cooldown-identical | 14 → 3 | 11 wake-only passes now earn 0.5 |
| repeat-cooldown-start-wait | 18 → 8 | wake-only passes and dry-run "starts" |
| repeat-cooldown-feed | 8 → 0 | every v1 pass was a wake |
| stale-cooldown-retry-start | 17 → 13 | 4 wake-only passes |
| repeat-pool-swap-retry | 15 → 12 | 3 wake/end-only passes |
| prog-timewall-quest19-to-20 | 14 → 11 | dry-run start / batch-feed bypass (the equivalence differences) |
| onboard-first-kami-vendor | 17 → 16 | the kami index is kept now: one try's vendor buy of 8757 (not on display) is a guess |
| risk-revive-then-heal | 20 → 19 | revive, then sleep |
| smoke: prog-sonnet-unspent / stale-travel-before-cooldown-stop / risk-unmanaged-lowhp | 6 → 21 / 10 → 20 / 13 → 14 | |

The other 17 ranking drills keep every verdict. On the ranking drills: 69 try-verdicts change, in 10 drills. The ranking pass rate goes .566 → .507.

**Item point-biserial** (corrected, against the rest score, 22 model-tries):

| set | mean r | reversed (r < 0) |
|---|---|---|
| v1, all 47 (audit baseline) | .162 | 11 |
| v1, the 27 ranking items | .160 | 6 |
| v1.1, the 27 ranking items | .155 | 9 |

- **Clear fixes.** take-trade −.34 → +.43, stamina n/a → +.22, and first-kami-vendor +.02 → +.08 (−.05 before the kami index was kept).
- **Wake = 0.5 on the timing items lowers their r.** stop-cooldown +.22 → −.07, cooldown-start-wait +.18 → −.10, cooldown-feed has no r (0%). The recorded passes there were mostly wakes, which was the right play under v1's rules.
- **Still negative**, as the audit said: the Luna level cluster (banked-xp −.10, levelup-belief −.09; travel rows cannot change what v1 models did after a gap), listing-buy −.14 (noise), wrong-node-stop −.23 (the stated goal only acts on new tries).
- **Treat these r values as a prior, not a verdict.** v1.1 needs its own administration.

## 7. What the integrated scorer changed (against `v11/specs`)

- **Refusal penalty, lesser credit, cooldown band, kami-rules: no change.** They are opt-in (`scoring.refusal_penalty`,
  `lesser`, `world.rules_library`), and v1.1 specs keep v1's replay rows, so they do not opt in. As a sensitivity check,
  adding `refusal_penalty: 0.15` to every v1.1 spec changes 81 ranking try-verdicts on the rc2 tries, and every ranking
  spec still passes the gate. Whether v1.1 should opt in is open.
- **Kami index kept:** vendor-drill equivalence 13/44 → 44/44. One v1.1 verdict changes: haiku#0 on first-kami-vendor,
  P → F (an off-display vendor buy).
- **move vs travel:** onboard-travel-not-move's recorded mistake (one-step move to 11) now fails, so the retired drill
  is clean. onboard-quest2-move-three keeps v1's forbid. No rescored verdict changes.
- **Battery additions** (always-level, start-then-level, complete-all-quests from the integration; collect-all and
  mistake-then-wake from this step) pass no ranking drill. They add complete-all-quests on prog-gpt52-complete-when-met and three plays
  on stale-travel-before-cooldown-stop (both smoke).
- **Bank:** v2.0-rc2, and rc3 to rc8 after it, pass `check_bank` with the larger battery.

## Caveats

- The fork state was folded from prefix reads, checked against each v1 note and fixed where wrong (quest19 HP, cooldown-feed room). Clocks are the last lens `servedAt` + 5 s, and cooldowns are relative to that.
- repeat-cooldown-feed's ~170 s cooldown is authored, not recorded.
- **Cooldown band** (H review minor 1). The four cooldown timing items now refuse an act in the first 4 s after
  `cooldown_until` without flagging it, as the S1 calibration (`spec/rules.py` `ACCEPT_FROM_S`) found the chain did;
  stale-cooldown-retry-start's oracle waits 104 s. This changes 7 more rc2 try-verdicts (62 → 69): r on the ranking
  items .172 → .155, reversed 7 → 9, pass rate .519 → .507. The rc2 tries were recorded on KamiBench, whose chain lag
  was not measured, so the S1 band may be too strict for them. Full credit from +4 s (no 0.8 band) is kept for v1.1.
- **Data.** The recorded v1 runs (`KAMIARENA_DATA`) and the rc2 tries (`KAMI_DRILLS_PLAYS`) are not public; the
  generator and the rescoring scripts need them, the tests do not.
- The rescoring is a sensitivity check. A v1.1 administration is needed before any of these drills enter a forecast.
